# Siete Issues iniciales para asignar en GitHub

Crea un Issue por módulo, usando la plantilla "Tarea de modulo", asignando
cada uno al integrante responsable. Reutiliza esta información:

1. `[C] Gestión de edificios` — propietario 1; archivos c/gestion.c y .h;
   aceptación: registrar, modificar, eliminar y listar, límites de capacidad.
2. `[C] Validación y entradas` — propietario 2; c/validacion.c y .h;
   aceptación: xi<xf, h>0, lectura robusta y errores informativos.
3. `[C] Horizonte visible` — propietario 3; c/horizonte.c y .h;
   aceptación: alturas máximas, tramos fusionados, huecos, ocultos, extremos repetidos.
4. `[C] Área y perímetro` — propietario 4; c/geometria.c y .h;
   aceptación: casos UNO, TOCAN, SUPERPUESTOS, SEPARADOS y OFICIAL.
5. `[C] Dos gráficos SVG` — propietario 5; c/graficos.c y .h;
   aceptación: rectángulos, horizonte, ejes, escala y etiquetas.
6. `[C] Guardar y cargar ciudades` — propietario 6; c/archivos.c y .h;
   aceptación: archivos correctos, malformados, inexistentes y carga atómica.
7. `[C] Menú, integración y pruebas` — propietario 7; c/main.c, c/tests/, CI;
   aceptación: conectividad, resultados actualizados y pruebas documentadas.

Cuando se integren los módulos C, crear siete Issues equivalentes con prefijo
`[Go]` y responsable correspondiente. No modificar `modelo.h` sin acuerdo.
